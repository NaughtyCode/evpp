# P2-13: PhysicsThread CV Wakeup — Replace Busy-Wait with Condition Variable

**Date:** 2026-05-28
**Status:** Complete
**Plan:** `./docs/tasks/infra_plan/p2/p2-13-physics-cv-wakeup.md`

## Summary

Replaced the 100µs spin loop in `PhysicsSystem::FetchResult()` with a
`std::condition_variable` notification pattern. The physics thread's EventLoop
now signals `result_cv_` after enqueuing a result, and `FetchResult` waits on
the CV with timeout instead of polling, eliminating CPU waste and latency jitter.

## Changes

### Modified Files

| File | Change |

| `src/runtime/physics/physics_system.cc` | `FetchResult()` replaced 100µs spin loop (`while + sleep_for(100us)`) with `WaitForResult(timeout)` call |

## Design

```
Before (busy-wait):                    After (CV notification):
  while (elapsed < timeout) {            physics_thread_.WaitForResult(remaining);
    result = TryDequeue();               result = TryDequeueResult();
    if (result) return result;
    sleep(100us);  // CPU waste
  }
```

### Notification Flow

```
PhysicsThread::EventLoop():
  result_queue_.enqueue(result)
  result_cv_.notify_one()        →→→  PhysicsSystem::FetchResult():
                                         result_cv_.wait_for(lock, timeout)
                                         TryDequeueResult()
```
