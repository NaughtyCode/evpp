# P2-17: ExportMongo X-macro Simplification

**Date:** 2026-05-28
**Status:** Complete
**Plan:** `./docs/tasks/infra_plan/p2/p2-17-export-mongo-xmacro.md`

## Summary

Replaced the 3-point manual registration pattern (include + RegisterMeta + AddToModule,
82 types × 3 = 246 maintenance points) with a single X-macro list (`mongo_types.def`).
`ExportMongo()` shrank from ~200 lines to ~30 lines. Adding a new MongoDB type now
requires changing only one line in `mongo_types.def`.

## Changes

### New Files

| File | Purpose |
|------|---------|
| `src/runtime/database/mongo_bind/mongo_types.def` | X-macro type registry — single source of truth for all 82 MongoDB binding types |

### Modified Files

| File | Change |
|------|--------|
| `src/runtime/database/mongo_bind/mongo_bind.cc` | `ExportMongo()`: replaced 82 manual `Register*Meta` calls + 60 manual `AddToModule` calls with 3 X-macro expansion blocks. Library-only types (Oid, BsonExt, MongoLog, MongoMisc) kept as manual calls. |

## Design Decisions

- **Module routing via `module[0]`**: The `bson` vs `mongoc` module split is handled by
  checking the first character of the module name in the X-macro expansion. `'b'` →
  bson module, `'m'` → mongoc module.
- **Library-only types**: Oid, BsonExt, MongoLog, and MongoMisc have `Get*Lib()`
  functions but no `Register*Meta()`. These remain as manual `AddToModule` calls.
- **Includes retained**: Each type's header still needs its `#include` for the
  `Register*Meta()`/`Get*Lib()` function declarations. This could be auto-generated
  in a future iteration.
